**Git words used in the table**
- **PULL** = `git checkout <your-branch>` then `git pull origin main`, so your branch gets everyone's merged work.
- **PUSH** = `git add <files>`, `git commit -m "X: message"`, then `git push origin <your-branch>`.
- **PR** = on GitHub, open a pull request from your branch into `main` and name the reviewer.
- **NEEDS** = work from another member that must be merged into `main` first.

**Branches:** A `a-list`, B `b-hash`, C `c-feature`, D `d-graph`, E `e-tests`

**Reviewers:** A's PRs go to B, B's to A, C's to E, D's to C, E's to D.

## Daily git routine for everyone
1. **Start of every session:** `git checkout <your-branch>`, then `git pull origin main`.
2. **Commit small:** `git add <your files>` and `git commit -m "B: add isDuplicate"`. Edit only your own files.
3. **End of session:** `git push origin <your-branch>`.
4. **When a piece works:** run `make asan` first (zero warnings), then open the PR.
5. **Reviewer:** reads the code, runs it, then approves. After approval the author merges and tells the team in chat.
6. **Shared files:** only E edits `Makefile`, `main.cpp` and `README.md`. If you need a change, message E. This avoids merge conflicts.
